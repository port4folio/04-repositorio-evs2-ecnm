# Informe Final - Evaluación Sumativa 2

## Introducción

El presente informe tiene como objetivo presentar el desarrollo de un Plan de Aseguramiento de Calidad para un proyecto de software, utilizando metodologías ágiles Scrum y herramientas colaborativas como Jira y GitHub.

El trabajo fue desarrollado de manera grupal, permitiendo organizar tareas, controlar versiones y documentar estándares de calidad para el sistema.

---

# Objetivos del proyecto

## Objetivo general

Desarrollar un plan de aseguramiento de calidad aplicando metodologías Scrum y herramientas de control de versiones.

## Objetivos específicos

- Organizar tareas mediante Jira.
- Gestionar versiones utilizando GitHub.
- Aplicar modelos de calidad de software.
- Definir métricas y estándares de calidad.
- Implementar control de cambios mediante pull requests.

---

# Herramientas utilizadas

## Jira

Utilizado para:
- Gestión de backlog.
- Creación de épicas.
- Organización de sprint backlog.
- Asignación de tareas.

## GitHub

Utilizado para:
- Control de versiones.
- Creación de ramas.
- Registro de commits.
- Integración mediante pull requests.

## Visual Studio Code

Editor utilizado para el desarrollo y documentación del proyecto.

---

# Metodología Scrum

El proyecto fue dividido en dos sprint principales.

## Sprint 1

- Configuración del proyecto.
- Organización del backlog.
- Integración con GitHub.
- Creación de ramas y commits.

## Sprint 2

- Elaboración del plan de calidad.
- Definición de métricas.
- Gestión de cambios.
- Consolidación del informe final.

---

# Modelos de calidad aplicados

## ISO/IEC 25010

Utilizado para evaluar atributos de calidad como:
- Usabilidad.
- Seguridad.
- Mantenibilidad.
- Eficiencia.

## IEEE 730

Aplicado como guía para estructurar el plan de aseguramiento de calidad.

## CMMI

Considerado como referencia para mejorar la organización y madurez de procesos.

---

# Integración con GitHub

El equipo trabajó utilizando ramas independientes por tarea.

Cada integrante realizó:
- Commits individuales.
- Push al repositorio remoto.
- Pull requests.
- Integración colaborativa.

---

# Gestión y control de cambios

El control de cambios se realizó mediante:
1. Creación de ramas.
2. Desarrollo independiente.
3. Revisión mediante pull requests.
4. Integración de cambios aprobados.

---

# Conclusión

La utilización de metodologías ágiles y herramientas colaborativas permitió mantener una adecuada organización del proyecto, facilitar el trabajo en equipo y asegurar una correcta gestión de calidad durante el desarrollo.
