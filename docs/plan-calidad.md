# Plan de Aseguramiento de la Calidad

## 1. Objetivos del plan de calidad

El objetivo principal de este plan es asegurar que el proyecto de desarrollo de software cumpla con estándares de calidad definidos durante todas las etapas del desarrollo.

También se busca:

- Garantizar el correcto funcionamiento del sistema.
- Mantener una adecuada organización del trabajo en equipo.
- Mejorar la trazabilidad de tareas mediante Jira y GitHub.
- Reducir errores mediante revisiones y control de cambios.
- Asegurar el cumplimiento de los requerimientos establecidos.

---

## 2. Roles y responsabilidades

### Product Owner
Encargado de definir los requerimientos del proyecto y priorizar las funcionalidades del sistema.

### Líder de QA
Responsable de supervisar el cumplimiento de los estándares de calidad y verificar el correcto desarrollo del proyecto.

### Desarrolladores
Encargados de implementar funcionalidades, realizar commits y trabajar en ramas independientes utilizando GitHub.

### Analista de pruebas
Responsable de revisar funcionalidades, detectar errores y validar el correcto funcionamiento del sistema.

### Encargada de roles y responsabilidades
Responsable de identificar y documentar las funciones principales de cada integrante dentro del proyecto.

### Responsabilidades del equipo
Cada integrante debe cumplir con las tareas asignadas en Jira, realizar commits en GitHub y participar en la revisión del plan de calidad.


---

## 3. Atributos de calidad

### Usabilidad
El sistema debe ser fácil de utilizar y comprender por los usuarios.

### Confiabilidad
El software debe funcionar correctamente sin presentar errores críticos.

### Mantenibilidad
El código debe estar organizado y documentado para facilitar futuras modificaciones.

### Eficiencia
El sistema debe responder correctamente y optimizar el uso de recursos.

### Seguridad
Se deben proteger los datos y controlar adecuadamente los accesos al sistema.

---

## 4. Modelos de calidad aplicados

### ISO/IEC 25010
Se utilizará como modelo principal para evaluar atributos de calidad como mantenibilidad, funcionalidad, seguridad y eficiencia.

### IEEE 730
Se aplicará como guía para la elaboración del plan de aseguramiento de calidad del proyecto.

### CMMI
Se utilizará como referencia para mejorar la madurez y organización de los procesos de desarrollo.

---

## 5. Métodos de evaluación

Para evaluar la calidad del sistema se utilizarán los siguientes métodos:

- Revisión de código.
- Validación de funcionalidades.
- Control de tareas mediante Jira.
- Revisión de pull requests en GitHub.
- Verificación del cumplimiento de objetivos por sprint.

---

## 6. Métricas de calidad

Las métricas utilizadas serán:

- Cantidad de tareas completadas por sprint.
- Número de errores detectados.
- Cantidad de commits realizados.
- Número de pull requests aprobados.
- Cumplimiento de historias de usuario.

---

## 7. Estándares de trabajo

El equipo utilizará los siguientes estándares:

- Uso de ramas independientes por tarea.
- Uso obligatorio de commits descriptivos.
- Organización de tareas mediante Jira Scrum.
- Uso de pull requests para integrar cambios.
- Documentación clara y ordenada del proyecto.

---

## 8. Gestión y control de cambios

El proceso de control de cambios será el siguiente:

1. Solicitud del cambio.
2. Evaluación del impacto.
3. Aprobación del cambio.
4. Implementación en una rama independiente.
5. Revisión mediante pull request.
6. Validación final e integración al proyecto.

Jira permitirá registrar y controlar las tareas, mientras que GitHub permitirá administrar versiones y cambios del sistema.

---

## 9. Evidencias del proyecto

Las evidencias consideradas para el proyecto serán:

- Product backlog en Jira.
- Sprint backlog.
- Historias de usuario.
- Ramas creadas en GitHub.
- Commits realizados por cada integrante.
- Pull requests del equipo.
- Documento final del plan de calidad.
